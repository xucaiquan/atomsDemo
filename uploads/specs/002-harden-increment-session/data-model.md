# Phase 1 Data Model: 增量可靠性与会话连续性加固

**Feature**: `002-harden-increment-session` | **Date**: 2026-09-21

> **重要**：本特性**不新增表、不新增列、不修改 `data_models/` schema**（见 research.md R-3）。本文件描述的是**既有实体上被本特性赋予新语义的字段与不变量**，以及状态机与时间关系。

## 实体

### 项目（Projects）

| 字段 | 本特性相关语义 |
|---|---|
| `public_id` | 对外唯一标识；内部自增 `id` 永不出现在响应中 |
| `owner_key` | 归属键。**列宽 64 是硬约束**——本特性要求派生侧保证长度无关的唯一性（见下「身份键派生规则」） |
| `is_demo` | 演示项目，对所有访客可见；**不属于越权** |
| `status` | 项目级状态，与活跃版本状态联动 |
| `updated_at` | 由 ORM 维护；**本特性不写入、不依赖其作为进度信号** |

**不变量**
- INV-P1：`owner_key` 相同的请求方可读写；`is_demo` 项目对任意身份只读可见。
- INV-P2：写路径只允许归属者本人（演示项目拒绝写入，返回 409 而非 404）。
- INV-P3：同一项目同时最多一个活跃版本；**该占用必须在版本落地终态后立即释放**（对应 spec SC-006）。

### 版本（Versions）

| 字段 | 本特性相关语义 |
|---|---|
| `seq` | 项目内单调递增 |
| `status` | `pending → running → succeeded \| failed \| cancelled`（见状态机） |
| `prompt` | 用户描述；**失败后必须保留**（FR-019） |
| `html` | 页面内容；**仅在 `succeeded` 时非空**，任何失败路径必须保持为空 |
| `html_sha256` | 内容摘要，与 `html` 同源同事务写入 |
| `summary` | 步骤摘要（面向用户）。**本特性新增在失败时记录异常类名**，但**不**混入内部控制字段（见 R-3） |
| `error` | 面向用户的失败说明：可读、无堆栈、无内部路径 |
| `error_type` | 失败类型；**任何失败路径都必须写入**（当前回收路径写入 `None`，属缺陷） |
| `updated_at` | **本特性的核心时间信号**：只在真实进展点推进（见「时间关系」） |

**不变量**
- INV-V1：终态一经写入不可被晚到结果覆盖。`ACTIVE_STATUSES = ("pending","running")` 守卫在**所有**写入路径（含预算超时路径）上生效。
- INV-V2：`status == "succeeded"` ⟺ `html` 非空且通过完整性校验（以 `</html>` 结尾 + 无重复文档结构）。
- INV-V3：失败版本的 `html` 必须为空——宁可无页面，不可有静默的半成品页面。
- INV-V4：`updated_at` 的推进必须与**真实进展**一一对应，不得由无条件定时器推进。

### 生成步骤（Generation_steps）

| 字段 | 本特性相关语义 |
|---|---|
| `seq` | 1 需求分析 / 2 结构设计 / 3 代码生成 |
| `status` | 同版本状态机 |
| `output` | 步骤产出；列表端点截断展示 |
| `started_at` / `ended_at` | 耗时来源 |

**不变量**
- INV-S1：**失败归因必须指向真实失败的阶段**，不得指向未启动的阶段（FR-014）。
- INV-S2：任一版本落地失败终态时，其下**不得存在**仍为 `running` 的步骤。已在成功阶段完成的步骤保持 `succeeded`（FR-015）。

### 身份（OwnerContext）

| 字段 | 语义 |
|---|---|
| `owner_key` | `user:<hash>` 或 `anon:<nonce>.<sig>` |
| `anon_key` | 匿名身份时为 `nonce.sig`；登录身份时为 `None` |

**身份键派生规则（本特性修正）**

| 形态 | 派生规则 | 长度 | 唯一性保证 |
|---|---|---|---|
| 匿名 | `"anon:" + nonce(32) + "." + sig(16)` | 5 + 49 = **54** | 32 hex nonce = 128 bit |
| 登录（**修正后**） | `"user:" + sha256(subject)[:32]` | 5 + 32 = **37** | 128 bit，长度无关 |
| 登录（**修正前，缺陷**） | `("user:" + subject)[:64]` | ≤ 64 | ❌ 长标识被截断后碰撞（已实证 3→1） |

**不变量**
- INV-I1：归属键必须**长度无关地**唯一——不得因列宽上限截断而合并（FR-024）。
- INV-I2：身份标识必须经签名保护；伪造者被拒绝并回落为新签发，**且不得读到他人数据**（FR-021）。
- INV-I3：请求体中的任何字段不影响归属（FR-020）。

### 整体时间预算（本特性引入的新概念，不落库）

| 概念 | 定义 |
|---|---|
| `GENERATION_BUDGET_SECONDS` | **420.0**。整条流水线（阶段1+2+3 及其全部重试与续写）从起点到终态的总预算 |
| `deadline` | 流水线启动时计算的单调时刻 `start + BUDGET`；**仅存在于内存** |
| `remaining` | `deadline - now`；每次模型调用前计算 |
| 单次调用的实际超时 | `min(STAGE_TIMEOUT, remaining)`，`STAGE_TIMEOUT = 120.0` |
| 预算不足时的行为 | 若 `remaining` 低于最小可用调用预算，**不再发起新调用**，直接以预算耗尽落库失败 |

## 状态机

```text
                 ┌──────────────────────────────────────┐
                 │                                      │
   pending ──▶ running ──┬──▶ succeeded                │
                 │       │                             │
                 │       ├──▶ failed      （上游失败 / 预算耗尽 / 内部错误）
                 │       │                             │
                 │       └──▶ cancelled   （用户取消，状态优先写入）
                 │                                      │
                 └──────────────────────────────────────┘
                    回收路径：running ──▶ failed（超出 STALE_AFTER 无进展）
```

**责任划分：谁负责写终态**

| 场景 | 责任方 | 时限 |
|---|---|---|
| 正常完成 | 流水线 | ≤ 预算 |
| 上游失败重试耗尽 | 流水线 | ≤ 预算 |
| 预算耗尽 | 流水线 | = 预算（硬） |
| 用户取消 | 取消接口（先写状态，再取消任务） | 即时 |
| 内部异常逃逸 | 流水线的通用兜底 | 即时 |
| **进程死亡 / 任务消失** | **回收路径**（惰性，在若干读写端点触发） | ≤ `STALE_AFTER` |

**关键点**：前五行覆盖了**所有活着的进程**；只有最后一行的责任在回收路径。这与当前实现的关键差别是——当前实现把第二到五行全部押在了"回收路径"上，而回收路径又被心跳废掉了。

## 时间关系（本特性的核心不变量）

```text
GENERATION_BUDGET_SECONDS   = 420s   (7 分钟)   ← 流水线自终结上限
STALE_AFTER                 = 600s   (10 分钟)  ← 回收阈值
FRONTEND_POLL_TIMEOUT       = 720s   (12 分钟)  ← 用户等待上限

必须成立：  420  <  600  <  720
```

**为什么这三者必须有序**

- `420 < 600`：活任务的**最长静默期**是阶段3 的预算（420s，因为阶段1/2 各约 20s 且会在 `versions` 上推进进展），必须严格小于回收阈值，否则活任务会被误杀——这正是心跳当初要解决的问题，现在由预算本身解决。
- `600 < 720`：回收必须**先于**前端放弃，否则用户永远等不到真实终态，只会看到界面超时（当前实现即是如此：界面 720s 放弃时，后端还有 6 倍于它的工作没做完）。

**校验方式**：这三个值必须以常量集中声明并附注释说明关系；测试断言 `BUDGET < STALE_AFTER < FRONTEND_POLL_TIMEOUT`（前端值经接口或常量对齐）。
